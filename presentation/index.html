02/16
Why
what a conformance pass still leaves open

90% of Roast — and still many corners to light.

Raku++ passed the large majority of Roast's ~216,000 assertions, and running ordinary Raku programs still turned up plenty to improve. Nearly every one of those findings came from somewhere other than Roast: writing example programs, running a corpus of real code, installing ecosystem modules, generating documentation sites.

Roast

Is this Raku?

The official specification suite — 1,462 files, ~216,000 assertions. It defines the language, test by test.

Rakugrid

Does it hold together?

Whether an implementation survives contact with real Raku programs. Built from what those findings taught us.

Not a replacement for Roast, and not a fork of it. Roast defines the language; Rakugrid measures whether an implementation of it holds together.

03/16
The gap
three things a specification suite is not for

Provenance. Exhaustiveness. Combinations.

01 · provenance

Every test says why

A bug we fixed, a corpus program that broke, a module that would not install, a documented rule. Nothing is here because it seemed like a good test — from: is a required field.

02 · exhaustiveness

Holes are visible

Coverage is measured against a machine-extracted inventory of the language: 182 operators, 198 subroutines, 667 methods, ~110 types. An atom with zero tests is a visible hole, not an unknown unknown.

03 · combinations

Crossings, systematically

Most hard bugs were constructs that each worked alone and broke together — return inside CATCH, next inside .map inside for, a dynamic variable crossing a regex subrule boundary.

Each of those bugs needed two or three constructs interacting, and none is reachable by testing either construct alone. That is the layer Rakugrid adds.

04/16
Vocabulary
three words, and the whole suite follows from them

Atoms hold the line. Molecules find the bugs.

the grid — eight orthogonal facet axes

atom

One construct exercising one behaviour in isolation. A point in the grid.

atoms prevent regressions

molecule

Constructs in combination, where each part is known to work alone. A covering array over the axes.

molecules find bugs

ladder

The corner values a position accepts — Inf, NaN, -0e0, empty, the bignum boundary, the type object.

what flows through the point

Identity is stable and citable: grid:operators/infix-plus#0041 — the atom, then a four-digit number unique within it, never reused and never renumbered. When a molecule fails, the shrinker walks the facet axes to the minimal failing coordinate; the result is a valid minimal repro and is promoted into atoms/ with its provenance intact.

The full cartesian product is ~74 million points before payloads — which is why this is generated as a covering array at a chosen interaction strength rather than enumerated. Empirical fault studies find essentially all defects triggered by six or fewer interacting factors, with 2-way already catching the large majority. Strength is a dial, not a constant.

06/16
Ladders
facets say where a construct sits — ladders say what flows through it

Corner against corner, in both directions.

Int0 · 1 · -1 · 2 · 2⁶³-1 · 2⁶⁴ · -2⁶⁴  — the bignum boundary both ways
Num0e0 · -0e0 · 1e0 · Inf · -Inf · NaN · a denormal · max finite
Rat0/1 · 1/1 · 1/3 · a denominator past uint64  — the Rat→Num boundary
Str"" · " " · "0" · a multi-codepoint grapheme · an embedded NUL · a very long string
List() · (1,) · nested · lazy · infinite · self-referential
Rangeempty (5..1) · 1..Inf · -Inf..Inf · reversed · non-numeric
undefinedthe type object · Any · Mu · Nil · an unhandled Failure

An atom is not covered because it has tests — it is covered when every position's ladder is complete and the legal crosses are exercised in both orders. Order matters even for operators that ought to commute, because "ought to" is precisely the thing under test. Real defects sit exactly there: Inf + -Inf must be NaN and not 0; -0e0 must survive an addition; a Rat whose denominator crosses uint64 must degrade to Num rather than wrap — a defect Raku++ actually shipped.

The atom carries a form with two holes and a ladder for each; the generator fills them and records the value and the type. Exactness survives the bignum boundary — 1/3 + 2**64 is still an exact Rat, 2**64 + 2**64 an Int that does not wrap — while a single Num operand degrades the whole expression, and -0e0 survives being added to itself. Inf + -Inf is NaN in both orders, which is exactly why the ladder crosses both. This one operator is 11 × 11 = 121 expressions.

A skeleton is an AST-shaped template with a hole; the payload goes in the hole, and the pair is the test. Composition guarantees the program is well-formed — and because the rule is known, the expected result can be derived rather than merely observed; where the oracle disagrees with the derivation, that is a finding. Same payload, different enclosure, different answer: last throws in a sub, ends the loop in a loop, and empties the sequence in a gather. The full crossing is 14 nesting levels × 10 exits = 140 programs, 46 of them carrying a divergence.

10/16
Adjudication
Rakudo is the oracle, but not the arbiter

Divergence is always possible. Never silent.

Every test stores both what the reference actually did (oracle:) and what we assert (expect:). Usually identical. Where they differ, the test carries a signed verdict with a rationale and a date — and a divergence with no verdict fails the build.

docsdocumentation is explicit and the implementation contradicts it
reasonneither docs nor implementation settle it; the ruling follows from the language's own consistency
impl-bugwe believe it is a defect; links the upstream issue
unanswerablethe implementation yields no observation at all — hang, OOM, crash
underspecifiedmore than one answer is legitimate; assert only the property they share
disputedunresolved; the test is parked and does not run

Standing rulings settle recurring questions once: IEEE-754 beats the reference (correctly-rounded values derived from 80-digit arithmetic, never from another libm); diagnostic wording is never asserted, only the exception type; unspecified order — hash and set iteration — is never asserted at all.

11/16
Format
line-oriented, greppable, diff-friendly — hundreds of thousands of records a run

One file per atom. One behaviour per record.

atom hangs/str-encode-invalid-argument source curated kind termination — the assertion is that the program ends - id 0001 from generator:gen/methods.raku · review:2026-08-15 code "".encode(0) finishes 5s oracle rakudo-2026.07 → TIMEOUT after 6s oracle rakupp-3.14.0 → utf8:0x<> verdict impl-bug why an encoding name that is not a string must fail, and no argument makes non-termination correct — one bad cell stalled the method matrix 87 min ruled 2026-08-15 against rakudo-2026.07
exactly one assertion per record

is · type · throws · output

Plus finishes, same-as, parses, no-parse. The first four run in-process, many to a program; the last four need a process each, because a parse failure or a hang would take every other test in the file down with it.

how an expected value is produced

Never written by a person

An is value is whatever the reference's .raku printed, copied verbatim — and compared as text. Text is what makes NaN equal NaN, keeps -0e0 distinct from 0e0, and survives values whose .raku the engine then refuses to re-compile.

12/16
Generators
generators are the source; oracle snapshots are the artifact

Seven generators, one command to re-oracle.

ladder.rakua hand-written table of 53 operators and methods crossed with their edge ladders — value assertions per cell
operators.rakuthe documented inventory — 125 infix, 18 prefix, 2 postfix — every one crossed with a ladder. An operator the language documents and nobody tested becomes impossible, not merely unlikely
methods.rakuasks the implementation what a type has — .^methods — and crosses each method with that type's ladder. One atom per type, so a hole is visible at a glance
regex.rakuconstructs × subjects × match forms, asserting derived facts — so($s ~~ /p/), .Str, .from — never Match internals, which differ for reasons that are not about matching
syntax.rakudeclarators, signatures, phasers, quoting — compiled with -c and never run: asserts only whether it compiles, never the wording of the diagnostic
laws.rakualgebraic laws over ladders as same-as — no oracle at all. An engine that disagrees with itself is wrong without anyone deciding what the right answer was
molecules.rakutwo facet axes crossed — the interaction layer, one atom per crossing

Plus import-regression.raku, which imports whole regression programs with their fixtures and provenance. Ladders are append-only — ids come from a cell's position and are permanent — so widening one costs only the new cells.

13/16
Safeguards
every item here exists because it went wrong — none is hypothetical

Probing a language is hostile terrain.

  • ▹Parenthesise the operands. 1/2 ** 2 parses as 1/(2**2) — without parens a cell silently tests something other than what its label says.
  • ▹Confirm compile failures against a real file. EVAL is not a file: Rakudo compiles sub { (0) ~~ (Nil) } happily from a file and dies on the identical text under EVAL. Of 38 flagged compile failures, 28 were EVAL artefacts.
  • ▹Compile-check in a different process. Compiling sub { EXPR } declares whatever EXPR declares, so every class-bearing cell reported a redeclaration that existed only inside the probe.
  • ▹Give every cell its own names. Ten cells declaring class C are ten redeclarations once packed into one dense program. Names are derived from the cell's coordinates.
  • ▹Probe the reference twice. .WHICH on a reference type carries an address — a test built from one run is flaky by construction. Any cell answering differently on two identical runs is parked.
  • ▹Never assert a non-answer. CRASH:1 was once written into an is field. A reference that crashed or hung gives us nothing to assert.
  • ▹Nothing dangerous, ever. Only value types are introspected, and anything that could reach the outside world is refused by name. A generated suite must never be able to delete a file because some type grew an .unlink.

Roadmap

Density is a dial. ~580k at the top of it.

L0  ~3kseconds — every build; touches every atom once
L1  ~30kunder a minute — the commit gate
L2  ~150ka few minutes — pre-push

  • ▹Not yet built: the atom and facet inventory extractors, ladder-completeness in cover, directed shrinking, and the remaining facet axes.
  • ▹Ahead: the Roast harvest — take what Roast covers, never what it contains: parse its 1,462 files, extract every assertion as a triple, emit a coverage map, and generate only where a shape is uncovered. Expected values always come from a fresh oracle run, never from Roast's literal.
  • ▹Then: corpus and module-battery mining, the illegality grid, and holes closed to zero — followed by a CI matrix across implementations.
16/16
Run it
the harness runs on any implementation and tests any implementation

Point it at an engine.

$rakugrid fire  # run everything, emit TAP
$rakugrid fire --engine=/path/to/engine  # …against another one
$rakugrid check  # the build rule: no unsigned divergences
$rakugrid diverge  # where recorded engines disagree, clustered
$rakugrid isolate grid:operators/infix-plus#0041  # any test, standalone

The two need not be the same implementation. rakupp bin/rakugrid fire tests Raku++, raku bin/rakugrid fire tests Rakudo, and --engine= overrides either. Nothing in the suite requires a particular implementation to be present — Rakudo is consulted for one thing only: knowing what a piece of code does.
